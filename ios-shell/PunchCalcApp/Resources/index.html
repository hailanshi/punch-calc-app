软件说明

📌 功能简介

一句话：本机不再打卡，直接读公司考勤和工资条，用公司工资条的口径把当月工资算给你看。

首次打开输入一次公司账号密码（「保存登录」默认已勾上），之后每次启动自动登录并读取，不用再点任何按钮。底部四个页签：首页（当月工资明细）、记录（每日工时）、公司（工资条对照 / 日考勤同步 / 月报签收）、设置（参数）。

🕐 数据来源与工时判定

每天的工时来自公司两个接口，取两者较大值（谁算得多用谁，保证不漏加班）：

· 日考勤（ctlKqDetail）：公司自己折算好的结果 —— calc_field1=正班、calc_field3=平时加班、calc_field5=周末加班、calc_field19=事假、calc_field20=病假、calc_field21=年假、calc_field24=婚假。
· 原始打卡（ctlKqsOriginCardRecord）：实时，但只有打卡时刻，按班次口径折算。

为什么两个都要：公司日考勤有延迟。实测 10/16 公司只给了正班 8h（缺 3h 加班）、10/17 周六整条还没更新，而打卡已经是 08:18~21:00。只读日考勤会少算。

档位以公司为准：公司若把某天记为休息日（f5>0 且无正班），就整天进休息日加班档，不让本机内置节假日表参与判断。实测 2026-09-20（周日）公司按周末给 11h，内置表却当调休补班日，会多算 3h。

假别分两类：
· 事假：扣正班工时，且当月全勤奖清零。
· 婚假 / 年假 / 病假：属带薪假，不扣工资、不影响全勤，只在记录里标注。
另外只有落在应出勤工作日的假才参与扣减：10/7 的婚假落在国庆假期里，那天本来就没算进应出勤，扣了就是重复扣。

班次口径（用于把打卡时刻折算成工时，一律取整数小时）：正班 = 落在 8:20-11:50 + 12:50-17:20 内的时长（满勤 8h）；加班 = 18:00 之后，正常 3h；迟到 / 早退才按实际扣减；周末与法定节假日上班整天计 11h。早到和 17:20 后的零星时间不计。

「漏卡」判定：公司考勤只覆盖到某天时，那天之后不判漏卡（公司还没出数据，不是你没上班）。实测 10/19 公司还没记录，不会被误判。

🧮 工资计算公式（公司工资条口径）

全部按公司工资条的真实算法，用 2026-07 / 08 / 09 三个月工资条逐个金额验证过：

正班合计 = 截至今日的应出勤工时 − 请假工时（不是实打卡工时）
正班工资 = 基本工资 ÷ 应出勤工时 × 正班合计
平时加班工资 = 平时加班工时 × (基本工资 ÷ 174 × 1.5)
周末加班工资 = 周末加班工时 × (基本工资 ÷ 174 × 2)
当月应发出勤工资 = 正班工资 + 平时加班 + 周末加班
奖金汇总 = (绩效 + 岗位 + 工龄) × (正班合计 ÷ 应出勤工时)
应发工资 = 出勤工资 + 奖金汇总 + 全勤奖 + 其它补贴合计（餐补在内）
实发工资 = 应发工资 − 个人社保 − 个税

餐补 = min(出勤天数 × 每日餐补, 每月上限)。公司实测：7 月 25 天×15=375 → 封顶 360；8 月 23 天=345、9 月 19 天=285 都没触发。

加班单价为什么要 ÷174 而不是 ÷应出勤工时：底薪折算用「应出勤工时」（如 176 / 168），加班单价折算用固定的 174（21.75 天 × 8，法定月计薪天数）。两者口径不同，混用会对不上工资条。

月底会自然收敛：月中的「截至今日」只算已经过去的工作日，到月末自动等于整月应出勤，和工资条一致。9 月实测：176 − 32(事假) = 144，正班工资 2209.09，与工资条逐分相同。

⚙️ 默认参数一览

基本工资 2700 元（按月保存，读工资条会自动写入）· 应出勤工时按「工作日×8」自动推算，读到工资条后自动换成工资条上的值 · 加班时薪分母 174（倍数固定 1.5 / 2 / 3）· 社保 420 元 · 全勤奖 100 元 · 绩效 50 元 · 岗位 400 元 · 工龄奖 0 元 · 每日餐补 15 元（每月上限 360）· 其他补贴 0 元 · 个税默认不计。

📋 记录导出格式

日期|类型|上班工时|正常工时|平日加班|周末加班|节假日加班|是否节假日|是否周末|备注

类型：work=上班（公司考勤），absent=请假/缺勤，holiday=法定节假日休息，rest=普通休息。支持追加 / 覆盖两种导入模式。

🏢 公司页（工资条对照 / 日考勤同步 / 月报签收）

底部导航第 3 个是「公司」页，用来跟公司系统（hr.voopootech.net）对数据。三件事：
① 网页工资条：读取公司在册工资条的全部项目。
② 工资条对照：把工资条每一项和本机算出来的同名项并排显示，逐项给出差额（本机 − 网页），一致显绿、不一致显红。
③ 日考勤 → 同步本机（自动覆盖）：公司折算好的每日正班 / 加班 / 请假工时，整月覆盖写入本机。

登录：源码里不预置任何账号。首次手输账号密码并勾上「保存登录」，之后启动自动登录并读取；登录失效才会回到登录页。登录以服务器返回为准 —— 密码错了会显示原因，改完直接重试。

两个接口的月份范围不同（重要）：
· 工资条：任意月份都能查（当月未结算会提示）。
· 考勤 / 打卡：只有本月和上月，查更早的月份服务端会回落到上月。
所以查更早的月份时只有工资条、没有考勤可同步；跨月时对照页会拦掉金额差额，只列工资条原始项。

参数会自动对齐：读一次工资条，会把「应出勤工时 / 基本工资 / 绩效 / 岗位 / 工龄 / 社保 / 全勤」按工资条写入，算出来自然一致。

✍️ 考勤月报签收

公司页的「考勤月报签收」读取 WPS「时薪考勤月报」，查询条件是年份 + 月份 + 工号 + 姓名（四个都必填）。
· 工号与姓名自动取自公司系统（每次读取数据时从考勤行里抓），不用手填；
· 年份月份由你填，默认按当前查看的月份预填。

点「去签收」会弹出覆盖全屏的签收窗口，四个条件已自动填好并查询；在该页面上手写签名，再点「确认签收」即可。签过的月份页面显示「已签收 + 签收时间 + 查看签名」，签收按钮会消失——签了就不能再签。

签收请求是页面 JS 加密后发出的，所以必须在 App 内打开真网页完成，不能由本程序代签。

🔒 数据与兼容性说明

打卡工资计算器 v2.8。数据保存在本机 localStorage。在 iPhone Safari「添加到主屏幕」可作为 PWA 使用；也可套入 WKWebView 壳打包为 TrollStore 可安装的 IPA。

公司页的账号密码只存在本机（勾选「保存登录」时才落盘），不会上传到任何地方；本程序的源码里不含任何账号信息。
